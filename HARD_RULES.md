# HARD RULES — Chira Launcher

These rules are **non-negotiable**. They are distilled from `plan.md` (§1.8 non-goals, §3.3 hard rules,
§4.9 ownership rules, §20 security) and from the working agreement for this repository.
They bind every contributor, human or AI. `CLAUDE.md` points here so AI agents load this file at session start.

**If a task seems to require breaking a rule: stop, explain the conflict, and ask. Never "just this once".**
A rule can only be changed by editing this file in a commit whose message says so — never implicitly.

Where a rule is machine-checkable it is enforced by `pnpm check:rules`
(`scripts/check-hard-rules.mjs`, also part of `pnpm verify` and CI). The **Enforced** column says how.

## 1. Process and Git

| ID    | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Enforced                     |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| HR-P1 | `plan.md` is the source of truth. **The only edits allowed are phase-status markers** (owner-authorized 2026-11-19): when work on a milestone (M00–M08) starts, progresses or finishes, update the `> **Status:**` line directly under that milestone's heading (`⬜ Not started` · `🟨 In progress` · `✅ Done`, plus a one-line note of what was verified and the commit). Never edit the plan's content, never delete or comment out a phase (that would hide the spec/acceptance criteria), and never mark a phase ✅ unless its **Exit** criteria were actually run and passed. If the plan looks wrong or conflicts with reality, say so and record the deviation in `docs/DECISIONS.md` — do not silently diverge and do not rewrite the plan to fit the code. | review                       |
| HR-P2 | **No destructive Git.** No force-push, no history rewrite (`reset --hard`, `rebase` of pushed work, `commit --amend` of pushed commits), no `clean -fd`, no discarding uncommitted changes, no deleting branches/tags — without explicit approval for that specific action.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | review                       |
| HR-P3 | **Never invent a remote.** Push only to a remote that already exists and was configured by the owner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | review                       |
| HR-P4 | **Never skip checks.** No `--no-verify`, no bypassing signing, no disabling lints/tests to get green. Fix the cause.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | review                       |
| HR-P5 | **Never claim something works unless it was run.** Report failures, skipped steps, and untested code plainly.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | review                       |
| HR-P6 | **No fake functionality.** No mock data presented as real, no stubs that pretend to succeed. ## 2. Windows safety (`plan.md` §1.8, §3.3, §20)

| ID     | Rule                                                                                                                                                                                                                                                            | Enforced                                   |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| HR-W1  | **Never inject into, hook, or modify the memory of other processes or games.** Outside-in management only. Banned APIs: `WriteProcessMemory`, `ReadProcessMemory`, `CreateRemoteThread`, `VirtualAllocEx`, `SetWindowsHookEx`\*, `LoadLibrary`-based injection. | `check:rules`                              |
| HR-W2  | **Never embed external apps in the webview.** No `SetParent` reparenting of foreign windows.                                                                                                                                                                    | `check:rules`                              |
| HR-W3  | **Never rely on constant topmost.** No `HWND_TOPMOST` / `WS_EX_TOPMOST` / `alwaysOnTop` for shell windows; overlays are raised only while active.                                                                                                               | `check:rules`                              |
| HR-W4  | **Never replace or kill Explorer, or change shell/startup registry values**, until the supervisor + tested escape hatch exist (M07) **and** the owner approves. Early development must never be able to strand the desktop.                                     | `check:rules` (registry/shell APIs banned) |
| HR-W5  | **Never trust a stored HWND or PID.** Validate window _and_ process identity before every destructive operation (HWNDs and PIDs are reused; none survive a reboot).                                                                                             | review                                     |
| HR-W6  | **Never strip window styles indiscriminately.** Save original style/ex-style/rect/state _before_ modifying any window, persist it, and restore on every exit path.                                                                                              | review                                     |
| HR-W7  | **Never auto-elevate.** The shell runs as a normal user. No `runas`, no manifest `requireAdministrator`.                                                                                                                                                        | `check:rules`                              |
| HR-W8  | **No silent registry edits** "to make settings look integrated." Native API → supported interface → `ms-settings:` fallback, in that order.                                                                                                                     | `check:rules`                              |
| HR-W9  | **Close ≠ terminate.** Closing a window never silently kills a process tree. Force-terminate is a separate, explicit, user-confirmed operation.                                                                                                                 | review                                     |
| HR-W10 | **Never promise** tiling/overlay over exclusive fullscreen, the UAC secure desktop, or the lock screen. Degrade honestly.                                                                                                                                       | review                                     |

\* A keyboard hook for Alt+Tab replacement is a _plan item_ (spike S4) — it needs that spike's written verdict and
explicit owner approval before the ban is lifted for that one purpose.

## 3. Architecture (`plan.md` §4, §4.9)

| ID    | Rule                                                                                                                                                                                                                                                                                                                                                | Enforced             |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| HR-A1 | **The frontend never touches Win32.** It sends typed intents through `apps/shell-ui/src/services/`; Rust performs and reports. `invoke(` / `@tauri-apps/api/core` may appear **only** under `src/services/`.                                                                                                                                        | `check:rules`        |
| HR-A2 | **All `unsafe` lives in `crates/platform-windows`.** Every other crate keeps `unsafe_code = "forbid"` (workspace lint). Every `unsafe` block carries a `// SAFETY:` comment.                                                                                                                                                                        | lint + `check:rules` |
| HR-A3 | **Tauri commands are the API boundary, not where logic lives.** `src-tauri/` stays thin; behaviour belongs in engine crates.                                                                                                                                                                                                                        | review               |
| HR-A4 | **The engine is independent of the UI.** No engine crate may depend on `tauri` or on frontend code. A UI crash must never take managed apps down.                                                                                                                                                                                                   | `check:rules`        |
| HR-A5 | **Ownership boundaries:** `window-manager` owns native HWND operations · `workspace-manager` owns workspace state · `layout-engine` is pure geometry and never touches windows · `process-manager` owns process lifecycle · `display-manager` owns monitor discovery · `overlay-manager` owns visibility/placement of every floating shell surface. | review               |
| HR-A6 | **Typed commands only.** No `execute_arbitrary_command`-style APIs, no shell passthrough, no frontend-supplied command lines or paths executed without a scoped, validated command. Validate and rate-limit.                                                                                                                                        | `check:rules`        |
| HR-A7 | **Persistent vs runtime state are separate.** Persist layouts/profiles/settings/themes; never persist HWNDs as truth. Writes are atomic (temp + rename). Recovery data lives in `recovery/`, independent of the database.                                                                                                                           | review               |
| HR-A8 | **The protocol is versioned.** Changing a command/event/DTO shape means: regenerate TS bindings (`pnpm bindings`), bump `PROTOCOL_VERSION` (Rust) **and** `EXPECTED_PROTOCOL_VERSION` (TS) for breaking changes. Never hand-edit generated bindings.                                                                                                | test                 |
| HR-A9 | **Don't build everything up front.** Establish boundaries; extract crates when a responsibility becomes real. No speculative abstractions.                                                                                                                                                                                                          | review               |

## 4. Security and privacy (`plan.md` §20)

| ID    | Rule                                                                                                                                                                                                            | Enforced      |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| HR-S1 | **Strict CSP.** Never `unsafe-eval`; never remote origins in the production CSP; `csp` is never `null`.                                                                                                         | `check:rules` |
| HR-S2 | **Least-privilege capabilities.** `src-tauri/capabilities/*.json` may not grant `shell:`, `fs:`, `http:`, `process:`, `dialog:` or wildcard permissions without an explicit owner-approved change to this file. | `check:rules` |
| HR-S3 | **No remote content in privileged webviews.** No CDN scripts/fonts/styles; assets are bundled. No `dangerouslySetInnerHTML`, `eval`, `new Function`.                                                            | `check:rules` |
| HR-S4 | **Local-first.** No telemetry, no network calls, no cloud account — unless the owner opts in explicitly.                                                                                                        | review        |
| HR-S5 | **Honest, scrubbed logs.** Log what failed and why; do not log secrets, and avoid logging window titles/paths beyond what diagnostics need.                                                                     | review        |

## 5. Quality and performance

| ID    | Rule                                                                                                                                                                                                                  | Enforced    |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| HR-Q1 | **Errors are handled explicitly.** No silently swallowed errors, no `unwrap()`/`expect()` in non-test Rust (clippy `unwrap_used`/`expect_used`), no empty `catch`.                                                    | lint        |
| HR-Q2 | **Nothing is committed red.** `pnpm verify` (format, lint, typecheck, rules, tests, build) must pass before a commit is made.                                                                                         | review + CI |
| HR-Q3 | **Event-driven, not polling.** No tight polling loops (`plan.md` §19.2). Reconciliation timers must be slow, bounded, and documented.                                                                                 | review      |
| HR-Q4 | **Motion discipline.** Animate `transform`/`opacity` only; never animate large-area `backdrop-filter`/`blur`/`box-shadow` per frame; every animation honors reduced-motion and the Performance quality profile.       | review      |
| HR-Q5 | **Glass communicates hierarchy; it doesn't cover everything.** Text-heavy surfaces use Solid Surface. Contrast must stay readable in every theme and quality profile.                                                 | review      |
| HR-Q6 | **Brand identity is derived, not invented:** product name is **Chira Launcher** (slug `chira-launcher`, id `com.chira.launcher`), derived from the root folder. Do not rename or introduce an unrelated product name. | review      |
