# Decisions and deviations

Where this implementation refines, or deliberately differs from, `plan.md`. The plan itself is not edited to match
(HR-P1); this file is the record. Newest last.

The generic `project-` prefix is dropped. Plan §26.1 (branding) stays open for the owner.                                                                                           |

| D06 | 2026-11-19 | Settings persist in SQLite `user_settings` plus an atomic **last-known-good snapshot** in `recovery/` — no `config/settings.json`.                                                                             | Satisfies §17 (versioned DB; last-known-good snapshot; recovery independent of the DB) with one source of truth. `config/` files return when input mappings arrive.                                                                                         |
| D07 | 2026-11-19 | Navigation is **in-memory state**, not a URL router.                                                                                                                                                           | A fullscreen desktop shell has no address bar, history or deep links; a router is an unneeded dependency.                                                                                                                                                   |
| D08 | 2026-11-19 | **No mock-data mode.** `pnpm dev:ui` in a browser shows an honest "engine not connected" screen. UI tests use a fake behind the `Transport` seam.                                                              | Plan §22's "experience track on mock data" is valid, but shipping fake data in the app conflicts with the no-fake-functionality rule (HR-P6). The seam makes a clearly-labelled dev mock easy to add later if wanted.                                       |
| D09 | 2026-11-19 | **Playwright is deferred**; Vitest + Testing Library cover UI today.                                                                                                                                           | Plan §21 names Playwright against a mocked engine. It needs a browser download and is most valuable once there are multi-window flows; the `Transport` seam already supports it.                                                                            |
| D10 | 2026-11-19 | **Window styling** is a standard decorated window with an opaque `#101114` background; no Mica/Acrylic, no transparency, no custom title bar.                                                                  | Transparent WebView2 + vibrancy on mixed-DPI multi-monitor is spike S3 (M00). Committing to it before the spike would be guessing. The shell paints its own wallpaper per plan §16.3.                                                                       |
| D11 | 2026-11-19 | `unsafe` blocks require a `// SAFETY:` comment **at the declaration site**, enforced by `pnpm check:rules`.                                                                                                    | Makes HR-A2 auditable. (The checker caught the first violation in this repo's own code.)                                                                                                                                                                    |
| D12 | 2026-11-19 | pnpm's supply-chain **minimum-release-age gate stays on**; versions younger than ~1 day are pinned one release back (vitest 5.1.0, jest-dom 7.0.1, lucide-react 1.74.0, tauri-cli 2.12.5, user-event 14.6.12). | pnpm auto-wrote an exemption list on first install; that was reverted instead of accepting it. | D13 | 2026-11-19 | Release profile keeps **unwinding panics** (no `panic = "abort"`).                                                                                                                                             | A panic in one task must not take the whole shell down (plan §20.9). | D14 | 2026-11-19 | **Shell redesign: sidebar removed; Home carousel + Dynamic Island + floating dock; always launches borderless fullscreen.** Supersedes the sidebar shell built in the first foundation commit. | The plan names three permanent anchors — Home, Dynamic Island, floating dock (§11, D6) — and says the shell "runs fullscreen" (§4.5). The §11.1 _wireframe_ shows a left nav list, which contradicts those anchors; the first pass followed the wireframe and deferred Island/dock to M05. That was the wrong reading: the owner's reference (PS5 home) and §11 intent win. The wireframe contradiction stays in the plan, unedited (HR-P1). |
| D15 | 2026-11-19 | Home's carousel contains **only real destinations** (built ones first, unbuilt ones tagged with their milestone), not placeholder games/apps. The Island shows only **real activities** (engine events, window mode). | HR-P6: no fake content. PS5-style artwork cards for apps/games arrive with the library (M04). Until then the "Running now" panel is real data from window discovery. |
| D16 | 2026-11-19 | **M01 started with read-only window discovery** (`window-manager` + `platform-windows::enumerate_windows`), on demand rather than WinEvent hooks. | It gives Home real content and is the prerequisite for everything in M01/M02. Event-driven discovery (`SetWinEventHook` + reconciliation, plan §5.2) is marked `TODO(M01)`. Window lists are refreshed on Home mount and shell focus, never on a timer (HR-Q3). Only exe _file names_ reach the UI. |
| D17 | 2026-11-19 | Fullscreen is Tauri's borderless `fullscreen: true` (never `alwaysOnTop`). Escape routes: F11, Island buttons, Alt+F4. `CHIRA_WINDOWED=1` starts windowed for development only. | HR-W3 forbids constant topmost; HR-W11 forbids locking the user in. |
| D18 | 2026-11-19 | **Owner-requested plan addition:** every app is shown with its own executable icon, upscaled for HD — no template icons (plan §11.1 note, new §11.4 "App icons", requirement UI-015). Added to `plan.md` at the owner's explicit request; HR-P1 updated to say content edits happen only on such a request. | Until icon extraction exists (a `platform-windows` Shell call + a cached, safe icon service), the Home "Running now" list uses deterministic letter tiles — that is the documented _fallback_, not the target. Honest constraint recorded in the plan: upscaling cannot invent detail, so the largest native icon size is always preferred and only smaller icons are upscaled. |
| D19 | 2026-11-19 | **Release pipeline:** tag-triggered GitHub Actions builds only the NSIS bundle and publishes it with `SHA256SUMS.txt` and notes from `CHANGELOG.md`. Two jobs: `build` (read-only token) and `release` (the only `contents: write`, using the preinstalled `gh` CLI instead of a third-party release action). Gates: tag on `main`, tag = every manifest version, non-empty changelog entry, full `pnpm verify`. Enforced by HR-S6. | Changelog-as-source-of-truth keeps release notes human-written and makes a release impossible without one, while still being automatic. A write-scoped job that runs no repository code limits the blast radius of a compromised dependency. Code signing is deferred (plan §26.2/§26.3); the notes say so. Untested on GitHub until the first tag/dry run. |

## Known gaps relative to the plan (not decisions — just not built)

Everything in M00–M08 except the foundation pieces listed in `README.md`. Notably absent by design: window
management (discovery is read-only), sessions, layouts, workspaces, hot-plug detection, supervisor, startup integration, dock,
Island, switcher, library providers, File Manager, plugins, automation.
