# Decisions and deviations

Where this implementation refines, or deliberately differs from, `plan.md`. The plan itself is not edited to match
(HR-P1); this file is the record. Newest last.

| #   | Date       | Decision                                                                                                                                                                                                       | Why                                                                                                                                                                                                                                                         |
| --- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01 | 2026-11-19 | Product identity derived from the folder `project-chira-launcher`: **Chira Launcher** / `chira-launcher` / `com.chira.launcher` / data dir `ChiraLauncher`.                                                    | The brief says to derive it from the root folder and not invent a name. The generic `project-` prefix is dropped. Plan §26.1 (branding) stays open for the owner.                                                                                           |
| D02 | 2026-11-19 | **Tauri 2.12**, not the 3.0 alpha that `cargo search` lists as newest.                                                                                                                                         | Plan D4 locks Tauri 2; an alpha is not a foundation.                                                                                                                                                                                                        |
| D03 | 2026-11-19 | **TypeScript 6.0.x**, not 7.x.                                                                                                                                                                                 | `typescript-eslint` declares `typescript <6.1.0`; TS 7 would break linting. Revisit when typescript-eslint supports 7. (`baseUrl` is also removed — deprecated in TS 6.)                                                                                    |
| D04 | 2026-11-19 | Added a **`desktop-engine`** crate (composition root) that the plan's §4.9 tree does not list.                                                                                                                 | Plan §4.1 requires the engine to be UI-independent and Tauri commands to hold no logic. Something must own the subsystems; putting that in `src-tauri` would break both rules. It stays `tauri`-free (HR-A4) and is what moves into its own process at M07. |
| D05 | 2026-11-19 | Added **`settings-manager`** now (plan lists it) but **not** the other crates.                                                                                                                                 | Settings are real functionality today. Plan §4.9: "Don't build every crate up front."                                                                                                                                                                       |
| D06 | 2026-11-19 | Settings persist in SQLite `user_settings` plus an atomic **last-known-good snapshot** in `recovery/` — no `config/settings.json`.                                                                             | Satisfies §17 (versioned DB; last-known-good snapshot; recovery independent of the DB) with one source of truth. `config/` files return when input mappings arrive.                                                                                         |
| D07 | 2026-11-19 | Navigation is **in-memory state**, not a URL router.                                                                                                                                                           | A fullscreen desktop shell has no address bar, history or deep links; a router is an unneeded dependency.                                                                                                                                                   |
| D08 | 2026-11-19 | **No mock-data mode.** `pnpm dev:ui` in a browser shows an honest "engine not connected" screen. UI tests use a fake behind the `Transport` seam.                                                              | Plan §22's "experience track on mock data" is valid, but shipping fake data in the app conflicts with the no-fake-functionality rule (HR-P6). The seam makes a clearly-labelled dev mock easy to add later if wanted.                                       |
| D09 | 2026-11-19 | **Playwright is deferred**; Vitest + Testing Library cover UI today.                                                                                                                                           | Plan §21 names Playwright against a mocked engine. It needs a browser download and is most valuable once there are multi-window flows; the `Transport` seam already supports it.                                                                            |
| D10 | 2026-11-19 | **Window styling** is a standard decorated window with an opaque `#101114` background; no Mica/Acrylic, no transparency, no custom title bar.                                                                  | Transparent WebView2 + vibrancy on mixed-DPI multi-monitor is spike S3 (M00). Committing to it before the spike would be guessing. The shell paints its own wallpaper per plan §16.3.                                                                       |
| D11 | 2026-11-19 | `unsafe` blocks require a `// SAFETY:` comment **at the declaration site**, enforced by `pnpm check:rules`.                                                                                                    | Makes HR-A2 auditable. (The checker caught the first violation in this repo's own code.)                                                                                                                                                                    |
| D12 | 2026-11-19 | pnpm's supply-chain **minimum-release-age gate stays on**; versions younger than ~1 day are pinned one release back (vitest 5.1.0, jest-dom 7.0.1, lucide-react 1.74.0, tauri-cli 2.12.5, user-event 14.6.12). | pnpm auto-wrote an exemption list on first install; that was reverted instead of accepting it. Revisit pins when releases age past the gate.                                                                                                                |
| D13 | 2026-11-19 | Release profile keeps **unwinding panics** (no `panic = "abort"`).                                                                                                                                             | A panic in one task must not take the whole shell down (plan §20.9). Panics are logged by a hook.                                                                                                                                                           |

## Known gaps relative to the plan (not decisions — just not built)

Everything in M00–M08 except the foundation pieces listed in `README.md`. Notably absent by design: window
discovery/management, sessions, layouts, workspaces, hot-plug detection, supervisor, startup integration, dock,
Island, switcher, library providers, File Manager, plugins, automation.
